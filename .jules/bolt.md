## 2024-05-24 - Async State Persistence with ThreadPoolExecutor
**Learning:** Saving chat history to disk in a synchronous `open().write()` operation blocks the main Discord event loop. However, trying to blindly offload it to a background thread using `copy.deepcopy()` or direct dictionary iteration can result in `RuntimeError: dictionary changed size during iteration` if new messages arrive concurrently.
**Action:** When offloading state serialization to a background thread in a Python async application, serialize the state to a string (e.g., `json.dumps()`) on the main thread first, then pass the string to the background thread. Use a single-worker `concurrent.futures.ThreadPoolExecutor` with an atomic write (`os.replace`) to guarantee sequential, non-overlapping file saves without corrupting data or blocking the main event loop.
